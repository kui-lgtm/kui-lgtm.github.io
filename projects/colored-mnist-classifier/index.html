성능을 만든 세 가지 판단

혼동 행렬, 단계별 성능 변화, 최종 추론 구조를 연결해 모델의 약점을 찾고 정확도를 높인 과정을 정리했습니다.

01 / Error map

오류는 모든 숫자에 고르게 생기지 않았다

대각선이 아닌 셀만 집계한 행렬입니다. 실제 4를 9로 본 사례가 19건, 9를 4로 본 사례가 11건이었고, 3을 8로 판단한 사례도 16건으로 두드러졌습니다.

  • 형태 유사성: 닫힌 고리와 획의 접합부가 비슷한 4·9, 3·8에서 혼동이 집중
  • 대상 축소: 3·4·7·8·9만 증강해 학습량을 통제
  • 실험 기준: 전체 정확도뿐 아니라 새로 맞힌 샘플과 새로 틀린 샘플을 함께 비교
다음 결정: 이 분석을 근거로 폰트 다양화와 ±5° 기울임 증강을 설계했습니다.
02 / Performance ladder

가장 큰 개선은 모델 교체가 아니라 흑백 전처리였다

03 / Inference contract

한 입력에서 세 개의 답을 만드는 2단계 구조

predict_colors는 컬러 이미지를 받아 전경색·배경색과 흑백 숫자 마스크를 만듭니다. 이 마스크만 predict_digit으로 전달하므로 색상 분류와 숫자 분류의 책임이 분리됩니다.

  1. Palette projection각 RGB 픽셀을 7색 팔레트 중 가장 가까운 색으로 매핑
  2. Area ranking가장 넓은 색을 배경, 두 번째 색을 숫자 전경으로 결정
  3. Shape inference전경 마스크를 784차원으로 펼쳐 OvO-SVC에 입력
  4. Output mergedigit·foreground·background를 하나의 결과로 결합
Engineering deep dive

모델보다 먼저 입력을 다시 설계

RGB 픽셀을 그대로 학습시키기보다 색상과 형태를 서로 다른 문제로 분리했습니다. 전처리만으로 가장 큰 성능 향상을 만들고, 남은 오류에만 증강과 하이퍼파라미터 탐색을 적용했습니다.

01 / Pipeline

색과 숫자를 두 갈래로 분리

각 픽셀과 7색 팔레트 사이의 제곱거리를 벡터화해 가장 가까운 색을 찾았습니다. 픽셀 수가 가장 많은 색을 배경, 두 번째를 전경으로 정하고 전경만 255로 남겨 숫자 모델에 전달했습니다.

02 / Model selection

동일 조건에서 네 모델을 비교

숫자 분류 후보를 동일한 흑백 입력으로 비교했습니다. Random Forest도 높은 성능을 보였지만, OvO-SVC가 98.08%로 가장 높아 최종 베이스 모델로 선택했습니다.

03 / Error-driven data

혼동 행렬을 증강 목록으로 변환

04 / Tuning

넓게 찾고, 좁게 재탐색

GPU 기반 cuML 환경에서 2단계 그리드 서치를 수행했습니다. 1차 탐색은 학습 데이터의 50%로 규모 순서를 찾고, 2차 탐색은 후보 주변을 5-fold 교차검증으로 세밀하게 비교했습니다.

  1. Coarse searchC=10, gamma=scale이 가장 유망한 구간임을 확인
  2. Fine searchC 2–18의 짝수, gamma 1e−8–9e−7 범위를 재탐색
  3. Final modelC=6, gamma=3e−7에서 accuracy와 F1 모두 98.82%

04 / Retrospective

성능 개선을 재현 가능한 실험으로

담당 범위

선정된 OvO-SVC의 혼동 행렬을 분석해 취약 숫자군을 찾고, 폰트 다양화와 기울임 증강을 설계했습니다. 이후 2단계 그리드 서치로 C와 gamma를 최적화했습니다.
