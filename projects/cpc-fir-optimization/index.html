Class Project Challenge

교과목 결과물을 심사 단계마다 발전시켰습니다

CPC는 차세대반도체 교과목에서 작성한 프로젝트 결과보고서를 평가하는 대회입니다. 1차는 기존 보고서로 서류 심사를 진행하고, 2차·3차 발표 심사부터 추가 실험과 보완 내용을 전후대비표와 함께 제출할 수 있습니다.

Competition context

Class Project에서 Engineering Iteration으로

교과목 프로젝트에서는 63-tap 대칭 FIR을 32개의 folded coefficient로 줄이고, 네 개의 SRAM과 MAC을 병렬로 동작시켰습니다. CPC에서는 이 수업 결과물을 출발점으로 심사 피드백과 추가 검증을 반영해 설계를 단계적으로 개선했습니다.

Second presentation review / Stability

2차 발표 심사에서 RTL의 기준을 명확하게

2차 발표 심사를 준비하며 곧바로 병렬 자원을 줄이기 전에, 상태 전환·카운터·가변 길이 입력·누산 비트 폭이 한 샘플 동안 일관되게 동작하도록 제어와 데이터 경로를 정리했습니다.

01 / FSM & counter

4-state 기준 설계에서 SUM을 제거

기존 제어기는 IDLE → MAC → SUM → IDLE로 결과를 넘겼습니다. 2차 개선에서는 SUM이 수행하던 출력 제어를 IDLE 기준으로 옮겨 IDLE → MAC → IDLE 흐름으로 단순화하고, 계수 기록을 위한 WRITE만 독립 상태로 유지했습니다.

  • State: IDLE·WRITE·MAC·SUM의 4개 상태에서 연산용 SUM을 제거
  • Counter: MAC 종료 후 11에 머물던 값을 0으로 복귀
  • Timing: IDLE에서는 항상 cnt=0을 유지해 clear와 다음 sample 시작점을 명확화
02 / Stable configuration

필터 길이를 한 번의 MAC 동안 고정

외부 입력 iNumOfCoeff를 enable 계산에 바로 사용하면 연산 도중 값이 바뀌었을 때 MAC별 활성 구간이 흔들릴 수 있습니다. 그래서 rNumOfCoeff를 추가하고 MAC 상태가 아닐 때만 값을 latch했습니다.

03 / Numeric path

중간 clipping 없이 끝에서 한 번만 포화

3-bit signed sample의 대칭 합은 4-bit, 16-bit signed coefficient와의 곱은 20-bit가 필요합니다. 최대 32개 folded coefficient를 누적할 때 필요한 5-bit 여유를 더해 MAC accumulator를 25-bit로 통일했습니다.

Positive112K → 336K25-bit 범위에서 유지
Clear336K → 0clear timing 분리
Negative−112K → −560K중간 16-bit clip 없음
결과: 각 MAC 또는 중간 adder에서 값을 자르지 않고, wide final sum 뒤에서만 signed 16-bit saturation을 적용하도록 기준을 통일했습니다.
Third presentation review / Resource

3차 발표 심사에서 병렬도를 절반으로

3차 발표 심사에서는 12 MHz 시스템의 600 kHz 샘플이 20클록마다 들어온다는 점에 주목했습니다. 최대 32개의 folded coefficient를 두 MAC이 16회씩 처리해도 clear·setup을 포함해 샘플 주기 안에 완료할 수 있어 자원을 더 줄일 수 있었습니다.

01 / Architecture trade-off

남는 시간으로 공간을 절약

20 cycles
한 sample period
32 ÷ 2
16 MAC cycles
4 cycles
clear·setup 여유

4개의 SRAM bank와 MAC을 각각 2개로 줄이고, 각 bank가 16개의 coefficient를 담당하게 했습니다. MAC frame은 cnt=0..16으로 고정하고 짧은 필터는 frame 자체를 줄이는 대신 유효 구간 이후의 MAC enable을 꺼서 output-valid 시점을 일정하게 유지했습니다.

  • cnt=0: accumulator clear와 setup
  • cnt=1..16: 두 경로가 최대 32개의 folded coefficient 누적
  • Masking: 짧은 필터는 필요한 cycle 이후 accumulator 값을 유지
  • Interface: 마지막 counter에서 oDone, 출력 latch cycle에서 oValid 발생
02 / Synthesis comparison

최상위 설계 LUT 38.7% 감소

2차 구조와 3차 구조를 같은 단위로 합성해 최상위와 하위 블록별 LUT·FF 사용량을 비교했습니다. 병렬 경로를 직접 줄인 MAC은 거의 절반, 제어기와 메모리 주변 로직도 함께 감소했습니다.

SoC / FPGA validation

시뮬레이션에서 실제 PYNQ 보드까지

팀은 최적화한 FIR을 AXI-Lite wrapper에 연결하고 PYNQ-Z2에서 coefficient를 갱신했습니다. RTL 시뮬레이션뿐 아니라 physical pin과 Logic Analyzer로 출력 파형을 확인했습니다.

01 / SoC integration

RTL을 독립 IP처럼 사용할 수 있게 확장

AXI-Lite slave wrapper는 PS에서 coefficient SRAM, 필터 길이, update flag를 제어할 수 있게 합니다. FIR은 내부 FSM이나 counter를 외부가 해석하지 않아도 oValid가 올라온 cycle의 oFirOut만 읽을 수 있도록 인터페이스를 정리했습니다.

0x00–0x7CCOEFF_RAM_00–3132개 folded coefficient write
0x80REG_NUM_COEFF[5:0]filter tap 수 지정
0x84REG_UPDATE_FLAG[0]update / normal mode 전환
02 / Board test

600 kHz sample enable과 필터 출력을 핀에서 관찰

PL의 signal generator가 10 kHz·70 kHz·150 kHz 정현파를 합성해 signed 3-bit 입력을 만들고, FIR 출력과 oValid·oDone을 물리 핀으로 내보냈습니다. Logic Analyzer에서 coefficient write, MAC timing, output-valid 흐름을 실제 클록 기준으로 확인했습니다.

03 / Cross-check

필터 종류를 바꿔도 예상한 형태를 유지

PYNQ의 Python 환경에서 NumPy로 LPF·HPF·BPF·BSF coefficient를 계산해 AXI-Lite로 전달했습니다. 측정 파형과 시뮬레이션은 sampling 및 3-bit quantization에 따른 차이는 있지만, 각 필터가 통과·차단해야 하는 주파수 성분의 전체 형태가 일치했습니다.

My contribution

RTL 자원을 줄이고 검증 가능한 기준을 만들었습니다

담당 범위

저는 CPC 2차·3차 발표 심사를 위한 보완 과정에서 RTL 부분을 담당했습니다. 기존 4-MAC·4-bank 구조의 timing budget을 다시 계산하고, 제어 흐름과 accumulator 폭을 정리한 뒤 2-MAC·2-bank 구조로 축소해 합성 자원 차이를 확인했습니다.

핵심 판단

“병렬 경로가 많을수록 좋다”가 아니라 600 kHz 처리량을 만족하는 최소 병렬도가 무엇인지 계산했습니다. 20클록 중 최대 16클록으로 32개 folded coefficient를 처리할 수 있어, 남는 시간 여유를 하드웨어 자원 절감으로 바꿀 수 있었습니다.

팀과의 경계

프로젝트 전체에는 AXI-Lite wrapper, PYNQ 제어 소프트웨어, 실제 보드 측정이 포함됩니다. 포트폴리오에서는 이들을 팀의 통합 결과로 구분하고, 제 개인 기여는 RTL 병렬도·제어 timing·wide accumulation과 합성 비교에 명확히 두었습니다.
