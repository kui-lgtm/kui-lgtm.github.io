Hardware / Input pipeline

Engineering deep dive

LCD 출력과 터치 샘플링의 SPI 채널을 분리하고, 원시 ADC 값에 여러 단계의 필터와 좌표 변환을 적용했습니다.

01 / Bus design

속도가 다른 두 SPI 경로

대용량 픽셀 전송이 필요한 LCD와 안정적인 샘플링이 필요한 터치를 별도 SPI 주변장치에 배치했습니다. 각 장치는 소프트웨어 NSS와 독립 CS를 사용합니다.

02 / Touch pipeline

좌표 신뢰도를 높이는 4단계

XPT2046의 PENIRQ가 Low일 때만 데이터를 읽고, 단순 평균 대신 범위·변화량·압력·EWMA를 순차 적용합니다. 손을 떼면 필터 상태를 초기화해 다음 터치가 이전 궤적에 끌려가지 않게 했습니다.

  1. 유효 범위X·Y가 150–3950 범위 밖이면 가장자리 노이즈로 보고 제외합니다.
  2. 스파이크 제한직전 좌표와의 차이가 한 축이라도 500을 넘으면 순간 튐으로 판단합니다.
  3. 압력 검사Z1·Z2로 패널 저항을 계산하고 10–700 범위의 입력만 유효 터치로 인정합니다.
  4. EWMA 평활화α = 0.3으로 현재 샘플과 직전 필터값을 결합해 미세 떨림을 줄입니다.
  5. 화면 좌표 변환보정 구간을 320×240으로 스케일링한 뒤 가로 방향에 맞게 축을 교환하고 반전합니다.
filtered = 0.3f * current + 0.7f * previous;

x = (raw_x - 350) * 240 / (3850 - 350);
y = (raw_y - 400) * 320 / (3900 - 400);

lcd_x = y;
lcd_y = 239 - x;
03 / Interaction

그리기 도구와 기획 전환

엔코더로 RED, GREEN, BLUE, WHITE, YELLOW, CYAN, MAGENTA, BLACK을 선택합니다. 일반 색상은 5×5 브러시로, BLACK은 30×30 영역을 덮는 지우개로 사용해 작은 화면에서도 빠르게 수정할 수 있게 했습니다.

  • 상태 표시: 화면 상단에 보정된 X·Y와 현재 색상 이름을 실시간 출력
  • 팔레트: 화면 하단 30픽셀 바에 16×16 과일 아이콘을 배치해 시각적 UI 구성
  • 초기 기획: 과일 베기 게임의 애니메이션과 물리 처리에서 프레임 드롭이 발생
  • 전환 판단: 기존 터치·이펙트 로직을 유지하면서 좌표 정밀도를 검증할 수 있는 그림판으로 범위를 재설계
  • 다음 개선: SPI DMA와 프레임 버퍼로 CPU 점유를 낮춘 뒤 원래의 과일 베기 게임으로 확장
검증 항목: 네 모서리 좌표, 엔코더 색상 전환, BLACK 지우개 크기, SPI 속도 차이에 따른 LCD·터치 안정성을 각각 확인했습니다.
03 / Overview

센서 좌표를 자연스러운 그리기 경험으로

구성

ILI9341 TFT와 XPT2046 터치 컨트롤러를 각각 SPI로 연결했습니다. 화면을 터치하면 보정된 좌표에 브러시를 그리고, 로터리 엔코더를 돌리면 컬러 팔레트와 지우개를 선택합니다.

핵심 과제

터치 컨트롤러의 원시 좌표와 LCD의 화면 좌표는 방향과 범위가 달랐습니다. 좌표를 그대로 사용하면 누른 위치와 그려지는 위치가 어긋납니다.

해결

원시 좌표를 화면 크기에 맞게 스케일링하고 축 방향을 보정했습니다. 터치 상태와 엔코더 카운터를 분리해 브러시 위치와 색상 선택이 서로 영향을 주지 않게 구성했습니다.

배운 점

센서 값을 읽는 것과 사용자가 기대하는 인터랙션을 만드는 일은 다릅니다. 좌표계 변환, 입력 노이즈, 화면 갱신 범위를 함께 고려하는 방법을 익혔습니다.
