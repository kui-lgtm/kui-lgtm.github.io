02 / Transform

스캔 코드에서 암호문까지

PS/2 프레임에서 얻은 스캔 코드는 PROGMEM의 두 키맵 중 하나로 변환됩니다. Shift 키 상태를 별도로 관리하고, 알파벳에만 Caesar shift를 적용해 숫자와 기호는 그대로 유지합니다.

  1. 11-bit frame 수집Start, 8-bit data, parity, stop을 클록 하강 에지마다 조립합니다.
  2. 키 상태 해석F0 break와 E0 modifier를 구분하고 좌·우 Shift 상태를 유지합니다.
  3. 이동값 정규화엔코더 값에 % 26을 적용해 알파벳 범위로 제한합니다.
  4. 출력 동기화암호문은 LCD, 원문과 현재 매핑은 UART, 조작 시점은 부저와 PWM LED로 피드백합니다.
int16_t s = shift % 26;
if (s < 0) s += 26;

if (ch >= 'A' && ch <= 'Z')
  return ((ch - 'A' + s) % 26) + 'A';
if (ch >= 'a' && ch <= 'z')
  return ((ch - 'a' + s) % 26) + 'a';
03 / Timing & UX

블로킹을 줄인 피드백 설계

Timer0의 1 ms tick을 기준으로 짧은 소리와 LED 밝기를 갱신합니다. 입력을 받은 뒤 기다리는 대신 종료 시각을 저장해 두고 메인 루프가 시간이 되었을 때 출력을 끕니다.

  • LED fade: 10 ms마다 OCR0B를 증감해 0–255 밝기 범위를 왕복
  • 키 입력음: 20 ms 동안 4옥타브 C음을 출력
  • 엔코더 피드백: 100 ms 동안 이동값을 8개 음계에 대응
  • LCD 정책: 16문자를 채우면 화면을 지우고 첫 칸부터 새 암호문을 표시
  • 현재 한계: 11비트 프레임의 parity·stop bit 오류를 명시적으로 검증하지 않으며 입력 기록을 보존하지 않음
다음 개선: PS/2 프레임 검증과 ring buffer를 추가하면 오류가 있는 패킷을 버리고, LCD 출력 중 들어온 연속 입력도 안전하게 보존할 수 있습니다.
02 / Overview

여러 입력을 끊김 없이 처리하는 인터페이스

구성

PS/2 키보드 스캔 코드를 문자로 변환하고, 로터리 엔코더가 지정한 0–25 범위의 이동값을 적용합니다. 변환 전후 문자열과 현재 설정을 LCD로 보여주고 LED와 부저로 조작 피드백을 전달합니다.

핵심 과제

키보드의 직렬 데이터는 클록 에지에 맞춰 비트를 수신해야 하고, 동시에 엔코더와 타이머 기반 출력도 처리해야 했습니다. 단순한 순차 처리로는 입력 누락과 화면 갱신 지연이 생길 수 있습니다.

해결

PS/2 클록의 외부 인터럽트에서 스캔 데이터를 수집하고, 타이머로 시스템 시간을 관리했습니다. 입력 해석과 화면 출력은 메인 흐름으로 분리해 인터럽트의 작업량을 줄였습니다.

배운 점

사람이 조작하는 장치에서는 계산 결과뿐 아니라 입력 시점과 피드백의 일관성이 사용성을 좌우합니다. 인터럽트와 상태 변수를 나눠 다중 입력을 관리하는 방법을 익혔습니다.
