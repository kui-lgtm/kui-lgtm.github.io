Reconfigurable FIR Filter

Architecture / Verification

구조와 파형으로 검증한 설계

컨트롤러 구조와 시뮬레이션 파형을 따라 메모리 접근, MAC 타이밍, 가변 탭, 포화 연산이 의도대로 동작하는지 확인했습니다.

01 / Control plane

공유 버스 위에서 접근 권한만 분리

네 SRAM은 write data와 local address를 공유합니다. WRITE 상태에서는 외부 주소의 상위 2비트를 디코딩해 한 뱅크만 선택하고, MAC 상태에서는 네 뱅크를 같은 주소로 동시에 읽습니다.

  • Mode FSM: IDLE·WRITE·MAC·SUM의 큰 동작을 결정
  • Upper-bit decoder: 6-bit 주소를 2-bit bank와 4-bit local address로 분리
  • MAC controller: 필터 길이와 counter를 비교해 필요한 연산 경로만 활성화
설계 의도: 데이터 배선은 공유하고 chip-select 제어만 분리해 bank가 늘어나도 인터페이스가 복잡해지지 않게 했습니다.
02 / Memory write

주소가 바뀔 때 선택되는 bank도 함께 이동한다

빨간 박스로 표시된 구간에서 iAddrRam[5:4]가 바뀔 때마다 해당 bank의 write 신호만 활성화됩니다. 같은 시점에 메모리 내부 값이 500, 206, -102처럼 순차 저장되어 주소 디코딩과 실제 데이터 기록이 일치함을 확인했습니다.

  • 관찰 신호: iAddrRam, iWrDtRam, 각 SRAM의 Csn/Wrn과 내부 memory array
  • 검증 기준: 선택되지 않은 세 bank는 MEM_NO_OP을 유지
  • 결론: 외부의 연속 주소 공간을 네 개의 물리 bank로 안전하게 분배
03 / MAC timeline

읽기 지연을 포함해 데이터와 enable을 같은 클록에 정렬

첫 번째 노란 기준선 뒤에서 counter가 SRAM 주소가 되고, 동기식 read 결과가 한 클록 뒤에 latch됩니다. 그 값이 대칭 delay tap과 곱해져 ACC에 누적되고, 마지막 MAC update 이후 SUM enable이 켜진 뒤 다음 샘플 시점에 oFirOut이 갱신됩니다.

04 / Reconfiguration

저장된 계수와 실제 사용하는 계수를 분리

SRAM의 사용 범위 밖에는 16'h7000을 dummy 값으로 채웠습니다. 그 상태에서 63·49·33·21 tap으로 길이를 줄여도 파형의 유효 응답 구간만 짧아지고 dummy 값은 출력에 나타나지 않았습니다.

  • 63 taps: 4개 MAC이 10 / 10 / 10 / 2회 동작
  • 33 taps: 앞의 2개 MAC만 10 / 7회 활성화
  • 21 taps: 10 / 1 / 0 / 0회로 불필요한 bank 연산을 차단
05 / Numeric safety

overflow를 wrap-around 대신 경계값으로 고정

큰 dummy coefficient와 3배 impulse로 16-bit 양수 범위를 의도적으로 넘겼습니다. 빨간·파란 응답이 겹치는 구간에서도 출력은 음수로 뒤집히지 않고 32767에 머물렀으며, 이후 음수 항이 더해질 때는 경계값에서 정상적으로 감소했습니다.

  • MAC 내부: 확장된 accumulator를 16-bit로 줄일 때 saturation_fixer 적용
  • 최종 합산: 두 양수의 합이 음수 부호로 바뀌면 MAX, 두 음수의 합이 양수로 바뀌면 MIN 선택
  • 검증 범위: 개별 MAC과 최종 adder tree 두 위치에서 포화 동작 확인
Engineering deep dive

메모리, 연산, 타이밍을 한 주기로 정렬

대칭 FIR의 folded 구조로 저장량과 곱셈 수를 줄이고, 4개 메모리 뱅크가 같은 주소를 병렬로 읽도록 구성했습니다. 제어 경로는 모드와 카운터를 기준으로 실제 필요한 MAC만 활성화합니다.

01 / Architecture

63 taps를 32 coefficients로 접기

선형 위상 FIR의 대칭성을 이용해 중심 tap 하나와 좌우 대칭 입력 쌍을 먼저 더한 뒤 동일 계수와 곱했습니다. 따라서 최대 63-tap 필터를 32개의 계수 저장소로 표현할 수 있습니다.

02 / My module

4-bank SRAM 접근을 모드별로 중재

담당한 SRAM_Controller_4Parallel은 WRITE 상태에서 외부 주소의 상위 2비트로 한 뱅크만 선택하고, MAC 상태에서는 네 뱅크를 동시에 read로 전환합니다. 내부 카운터가 네 뱅크의 공통 하위 주소가 됩니다.

if (state == MAC && mem_cmd == READ) begin
  {csn[0], wrn[0]} = MEM_READ;
  {csn[1], wrn[1]} = MEM_READ;
  {csn[2], wrn[2]} = MEM_READ;
  {csn[3], wrn[3]} = MEM_READ;
  address = counter;
end else if (state == WRITE && mem_cmd == WRITE) begin
  case (external_address[5:4])
    2'b00: bank0 = MEM_WRITE;
    2'b01: bank1 = MEM_WRITE;
    2'b10: bank2 = MEM_WRITE;
    2'b11: bank3 = MEM_WRITE;
  endcase
end
  • WRITE: 6-bit 외부 주소를 bank select 2-bit + local address 4-bit로 분해
  • MAC: 동일 local address의 계수 네 개를 한 주기에 병렬 인출
  • IDLE / SUM: 모든 chip select를 비활성화해 의도하지 않은 접근 차단
03 / Control timing

20 clocks 안에서 읽고 누산하고 합산

12 MHz 시스템에서 600 kHz 샘플링 펄스는 20클록마다 발생합니다. FSM은 샘플 도착 후 MAC 상태로 진입하고, 카운터와 필터 길이를 비교해 유효한 뱅크만 활성화한 뒤 SUM에서 결과를 합칩니다.

  1. IDLEsampling pulse 또는 coefficient update flag를 대기
  2. WRITE외부 주소로 선택한 SRAM bank의 계수를 갱신
  3. MACcounter 주소로 4개 계수를 읽고 곱셈·누산 수행
  4. SUM4개 MAC 출력을 saturation adder tree로 합산

05 / Retrospective

파형에서 원인을 좁혀 가는 RTL 디버깅

담당 범위

4-Parallel SRAM controller를 설계하고, SeqMac과 AdderWithSat 테스트벤치를 맡았습니다. 팀원과 주소·제어 신호 규격을 맞추며 top-level 데이터 경로가 일관되게 연결되는지 확인했습니다.

검증 관점

RTL에서는 코드 한 줄의 논리뿐 아니라 신호가 유효해지는 클록이 중요했습니다. 블록도와 시뮬레이션 파형을 번갈아 보며 write/read 주소, delay tap, 누산 결과가 같은 샘플을 가리키는지 추적했습니다.

2026 CPC 발표 심사에서 실현

이 개선안은 2026 프로젝트 보고서 챌린지의 2차·3차 발표 심사 보완으로 이어졌습니다. iNumOfCoeff latch와 25-bit 누산으로 연산 기준을 안정화하고, 20클록의 sample period를 이용해 SRAM·MAC을 4개에서 2개로 축소했습니다. CPC FIR RTL Optimization에서 후속 과정을 확인할 수 있습니다.

배운 점

여러 모듈의 인터페이스가 얽힌 RTL은 문제를 구조적으로 분리해야 디버깅할 수 있었습니다. 최종 출력에서 시작해 합산, 누산, 메모리, 제어 신호 순으로 역추적하는 방식에 익숙해졌습니다.
