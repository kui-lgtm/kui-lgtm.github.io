Edge to insight

측정에서 제안까지 이어지는 시스템

비 IoT 장비에 센서와 릴레이를 결합하고, 수집·저장·분석·시각화·제어 기능을 독립 모듈로 나눠 확장 가능한 구조를 만들었습니다.

01 / Architecture

센서 노드와 분석 서비스를 느슨하게 연결

ESP32-C3가 전력·온습도·조도 값을 수집해 Mosquitto MQTT 브로커로 발행합니다. Docker Compose가 API, MySQL, AI 분석, 웹 화면, LLM 기반 ESG 모듈을 분리해 운영하고 결과를 다시 사용자 화면과 제어 경로로 전달합니다.

  1. Sense전류·온습도·조도 측정과 상태 LED 표시
  2. PublishWi-Fi와 MQTT로 시계열 데이터 업링크
  3. Analyze저장·전처리·NILM·이상 탐지 수행
  4. Act대시보드·ESG 요약·릴레이 제어로 결과 연결
02 / Physical layer

비 IoT 장비를 측정 가능한 장치로 전환

콘센트형 구조를 사용해 기존 장비를 개조하지 않고 전력 사용량을 관찰하고 원격으로 전원 라인을 제어하도록 설계했습니다.

  • ACS712: 전류를 측정해 소비전력과 이상 상태 판단에 활용
  • DHT22 · CDS: 온습도와 밝기를 에너지 사용 맥락으로 결합
  • Relay · LED: 원격 ON/OFF와 장치 상태 피드백 제공
03 / Monitoring

원시 센서 값을 운영 정보로 변환

현재 전력과 온도·습도·조도를 함께 표시하고, 시계열 그래프에 이상 지점을 구분해 사용자가 변화와 경고 원인을 빠르게 파악하도록 구성했습니다.

인터페이스 목적: 실시간 상태 확인과 장기 패턴 분석을 같은 데이터 흐름 위에서 제공하는 것입니다.
04 / Detection

이상 상태를 값이 아닌 사건으로 전달

센서 값과 환경 데이터를 결합해 이상 징후를 판단하고, 위험도·발생 시각·대상 장치를 알림으로 남깁니다. 사용자는 그래프를 계속 감시하지 않아도 조치가 필요한 상태를 확인할 수 있습니다.

  • 입력: 전력, 실내 온습도, 외부 환경 맥락
  • 판단: 임계치와 분석 모델을 이용한 비정상 패턴 구분
  • 출력: 실시간 알림과 누적 이상 건수
05 / ESG feedback

측정 데이터를 행동 가능한 월간 지표로 정리

프로토타입 화면은 월별 소비전력과 탄소 배출량, 예상 전기요금, 이상 감지 건수를 함께 보여주고 이전 달과의 변화를 바탕으로 등급과 종합 의견을 제시합니다.

My contribution

데이터가 다시 학습으로 돌아가는 구조

제 담당은 센서 데이터를 모으는 단계에서 끝나지 않았습니다. 수집 기준과 라벨 규칙을 정하고, 버전·전처리·분석 결과가 다음 학습 실험으로 이어지도록 데이터 운영 흐름을 정리했습니다.

01 / Data contract

수집 기준과 라벨 규칙 정의

시간대별 전력 시계열과 온습도·조도 정보를 같은 기준으로 결합할 수 있도록 데이터 항목과 수집 간격을 정리했습니다. 기기 상태와 이상 구간을 학습 데이터로 사용할 수 있도록 라벨링·증강 절차도 함께 설계했습니다.

  • 학습 단위: 슬라이딩 윈도우와 기기 상태 라벨을 모델 입력에 맞게 구성
  • 추적성: 데이터셋과 전처리 결과를 버전으로 관리해 실험 기준 유지
02 / Model strategy

지연과 정밀도에 따라 두 모델 비교

전력 총량에서 기기별 사용을 추정하는 NILM 문제에 Seq2Point와 UNet-NILM을 적용했습니다. 두 모델을 동시에 고정하기보다 실시간 응답과 정교한 시퀀스 분석이라는 목적에 따라 선택·비교했습니다.

ModelPredictionUse case
Seq2Point입력 창 중앙 시점의 기기 전력저지연 추정과 실시간 활용
UNet-NILM전 구간 전력 + ON/OFF 상태세밀한 기기 분해와 패턴 분석
재현성: 장치 자동 선택, 로그·결과 폴더 규격, 무작위 고정값, 임계치와 오차 지표를 문서화해 실행 조건을 통제했습니다.
03 / Feedback loop

분석 결과를 다음 데이터 버전에 반영

모델 결과의 오차와 이상 구간을 다시 확인해 라벨·전처리·윈도우 설정을 조정하는 피드백 루프를 운영했습니다. 실험 결과가 파일마다 흩어지지 않도록 로그와 산출물 형식을 표준화했습니다.

  1. Collect센서 스트림과 기기 운전 상태를 함께 기록
  2. Validate누락·범위·동기화 오류를 확인하고 정제
  3. Train동일한 데이터 버전과 실행 규칙으로 모델 비교
  4. Review오차 구간을 라벨·전처리 규칙에 다시 반영
System debugging

실환경에서 드러난 세 가지 경계

센서 신호, RTOS 태스크, 컨테이너 네트워크처럼 서로 다른 계층의 문제가 한 시스템 안에서 연결됐습니다. 각 문제를 관측 가능한 단위로 나누고 원인을 좁혔습니다.

01 / Signal

교류 센서 노이즈와 유효값 계산

전력 센서 값이 불규칙하게 변동해 센서를 교체한 뒤에도 교류 파형의 노이즈가 남았습니다. 오실로스코프로 신호를 확인하고 DSP 관점의 유효값 계산을 적용해 미세한 교류 전압에서 사용할 측정값을 만들었습니다.

02 / Firmware

FreeRTOS 자원과 동기화 조정

ESP32 태스크의 stack size 부족으로 전체 동작이 중단되는 문제를 파라미터 모니터링과 재조정으로 해결했습니다. 센서 측정 시점을 맞추기 위해 우선순위를 다시 배분하고 mutex·semaphore를 적용했습니다.

03 / Infrastructure

컨테이너 통신 실패를 계층별로 추적

비동기 네트워크 처리와 Docker Compose의 서비스 이름 기반 DNS가 충돌해 MQTT 데이터가 웹 클라이언트까지 도달하지 않는 문제가 발생했습니다. 주소 해석과 컨테이너 시작 시점을 분리해 점검하고, 명시적 주소 참조로 통신 경로를 안정화했습니다.

04 / Retrospective

하나의 기능보다 전체 흐름을 운영

담당 범위

데이터 수집 기준과 라벨링·증강 프로세스를 설계하고, 시계열 전력 데이터셋의 버전 관리와 전처리 자동화를 담당했습니다. 학습 결과가 다음 데이터 정제와 실험으로 연결되도록 분석 피드백 루프도 운영했습니다.

팀에서의 연결 지점

센서·서버·웹·AI 담당자가 같은 데이터를 다르게 해석하지 않도록 필드와 결과 형식을 조율했습니다. 주 2회 회의와 코드 리뷰, Git·공유 문서를 이용해 인터페이스 변경과 진행 상황을 공유했습니다.
