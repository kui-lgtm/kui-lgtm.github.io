Engineering deep dive

데이터 구조부터 바꾼 최적화

픽셀마다 RGBA를 건너뛰는 구조를 채널별 연속 배열로 바꾸고, ARM의 다중 로드·저장과 비트 연산으로 루프 비용을 줄였습니다.

01 / Memory map

입력과 결과 영역을 명시적으로 분리

HEX 이미지의 IDAT 시그니처를 찾아 실제 데이터 시작 주소를 얻고, 처리 단계마다 고정된 출력 영역을 사용했습니다. 입력 이미지가 위치한 0x40000000 영역과 런타임 R/W 영역을 분리해 초기화 과정의 충돌을 피했습니다.

02 / Assembly

함수별 병목에 맞춘 명령어 선택

모든 함수에 같은 최적화를 적용하지 않았습니다. 비교·반전·가중합이라는 서로 다른 연산 특성에 맞춰 처리 묶음과 레지스터 사용 방식을 달리했습니다.

FunctionBatchKey instructionsOptimization
Red pixel count16 px / loopLDMIA · AND · LSR · ADDGE4개 레지스터에 16바이트를 로드하고 분기 없이 조건부 누적
Image negative16 B / channelLDMIA · MVN · STMIAR/G/B 각 채널을 레지스터 단위로 반전하고 한 번에 저장
Grayscale8 px / loopADD · LSL · STRHMUL 대신 시프트·덧셈으로 3R + 6G + B 계산
핵심 차이: 기존 RGBA 배열은 다음 R값을 읽을 때마다 Alpha를 포함한 4바이트 간격을 건너뜁니다. 재배치 후에는 채널 데이터가 연속이므로 다중 레지스터 명령이 효율적으로 작동합니다.
03 / Verification

속도와 결과를 함께 확인

최적화 전후의 출력 메모리를 비교해 Red count, negative image, grayscale이 동일한지 먼저 확인한 뒤 실행 시간을 측정했습니다. 결과가 다른 빠른 코드는 성능 개선으로 인정하지 않았습니다.

  • Red count: 2.401 ms → 0.840 ms, 약 2.86× 향상
  • Image negative: 4.416 ms → 0.588 ms, 약 7.51× 향상
  • Grayscale: 4.224 ms → 2.737 ms, 약 1.54× 향상
  • 측정 범위: 함수별 프로젝트를 분리하고 종료 직전 정지점을 사용해 초기화·종료 루틴의 시간을 제외
  • 문제 해결: 시작 전 0 초기화가 HEX 데이터를 덮는 문제를 R/W 영역을 0x30000000대로 옮겨 해결
관찰: 단순 비트 반전은 MVN과 16바이트 다중 전송의 효과가 커 7.51×까지 개선됐지만, grayscale은 채널 결합과 16-bit 저장 연산이 남아 상대적으로 개선 폭이 작았습니다.
06 / Overview

데이터 배치부터 명령어까지 최적화하기

프로젝트 범위

32-bit RGBA 데이터에서 Red 값이 128 이상인 픽셀을 세고, 24-bit RGB 네거티브 이미지와 16-bit 그레이스케일 이미지를 생성했습니다. 동일한 기능을 C와 ARM 어셈블리로 각각 구현해 결과와 실행 시간을 비교했습니다.

담당 구현

main.c와 Red pixel count, Image Negative, Grayscale, Memory relocation의 C·ARM 코드를 작성했습니다. 재배치 이후의 함수와 추가 최적화 버전까지 구현하고, 메모리 맵과 결과 데이터를 확인하며 디버깅했습니다.

최적화 전략

픽셀마다 RGBA 4바이트를 순회하던 구조에서 Alpha를 제외하고 R·G·B 채널을 연속 영역으로 재배치했습니다. 이후 LDMIA와 STMIA로 여러 바이트를 한 번에 처리하고, MVN과 시프트·덧셈을 활용해 반복 횟수와 연산 비용을 줄였습니다.

문제 해결

HEX 데이터가 초기화 구간과 충돌하던 문제는 입력 영역과 R/W 메모리 맵을 분리해 해결했습니다. 함수별 성능 측정을 위해 코드를 모듈화하고 종료 지점 직전에 정지점을 배치해 측정 범위를 명확히 했습니다.

배운 점

알고리즘이 같아도 데이터의 메모리 배치와 명령어 선택에 따라 실행 시간이 크게 달라질 수 있음을 확인했습니다. 최적화는 속도만 줄이는 작업이 아니라, 동일한 출력의 검증과 측정 조건의 통제가 함께 필요한 과정이었습니다.
